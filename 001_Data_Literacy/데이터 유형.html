데이터는 어떻게 생겼느냐에 따라 4가지로 나뉩니다. 숫자인지 아닌지, 정수인지 소수인지, 순서가 있는지 없는지만 파악하면 됩니다.

이산형 데이터
Discrete Data
수치형
🔢
하나, 둘, 셋… 딱 떨어지는 정수값입니다.
1.5개, 2.7명처럼 중간 값이 존재하지 않습니다. "셀 수 있는" 것들이 모두 이산형입니다.
🧺
비유: 쇼핑 카트에 담긴 물건을 세는 것과 같습니다. 물건은 1개, 2개, 3개는 있어도 1.5개는 있을 수 없습니다. 사람 수, 클릭 횟수, 주문 건수 — 모두 이렇게 딱 떨어집니다.

숫자선 — 점(●)만 존재, 사이는 비어있음
0 1 2 3 4

점과 점 사이에는 아무 값도 없습니다.
2번째 점과 3번째 점 "사이"로 이동할 수 없습니다.

연속형 데이터
Continuous Data
수치형
📏
측정하는 값으로, 소수점 아래로 끝없이 세밀해질 수 있습니다.
측정 도구가 정밀할수록 더 자세한 값을 얻을 수 있습니다. 두 값 사이에는 항상 또 다른 값이 존재합니다.
🌡️
비유: 줄자로 키를 재는 것과 같습니다. 보통 줄자로는 160cm지만, 더 정밀한 도구로 재면 160.5cm, 더 정밀하면 160.52cm, 160.523cm…로 끝없이 세밀해집니다. 두 값 사이에는 언제나 또 다른 값이 있습니다.

3
명목형 데이터
Nominal Data
범주형
🏷️
순서가 없는 이름·범주 데이터입니다.
값들은 그냥 "종류가 다를 뿐"이며, 어느 것이 더 크거나 작다고 말할 수 없습니다. 숫자로 코딩해도 그 숫자는 크기를 뜻하지 않습니다.
🪣
비유: 여러 색깔의 양동이에 물건을 분류하는 것과 같습니다. 빨간 양동이, 파란 양동이, 노란 양동이 — 그냥 다른 종류일 뿐입니다. 빨강이 파랑보다 "더 크다"거나 "더 좋다"는 뜻이 없습니다.

카드 > 현금 — 이런 비교는 의미 없음
혈액형 — 그냥 "다름", 순서 없음
A형
B형
O형
AB형
숫자 코딩 예: A=1, B=2, O=3, AB=4
하지만 이 숫자는 크기가 아닙니다.
"AB형(4)이 A형(1)의 4배" — 아무 의미 없는 말입니다.

순서형 데이터
Ordinal Data
범주형
🥇
범주 사이에 순서가 있는 데이터입니다.
명목형과 달리 크고 작음을 비교할 수 있습니다. 하지만 각 단계 사이의 간격이 동일하다고 보기 어렵습니다.
🏁
비유: 달리기 경주 결과와 같습니다. 1등 > 2등 > 3등 순서는 알 수 있습니다. 하지만 1등과 2등의 격차가 2등과 3등의 격차와 꼭 같지는 않습니다. 만족도 점수도 마찬가지 — 1점→2점과 4점→5점의 체감 차이가 다를 수 있습니다.

🔢 이산형 수치형 ❌ 정수만 ✅ ✅ 주문 건수, 고객 수 ✅
📈 연속형 수치형 ✅ 무한 정밀 ✅ ✅ 키, 온도, 매출액 ✅
🏷️ 명목형 범주형 해당 없음 ❌ ❌ 혈액형, 결제 수단 ❌
🥇 순서형 범주형 해당 없음 ✅ ❌ 만족도, 회원 등급 ⚠️ 주의
이산형 vs 연속형
"1.5개가 가능한가?"
불가 → 이산형 / 가능 → 연속형
주문 1.5건은 없다 → 이산형
키 160.5cm는 있다 → 연속형
명목형 vs 순서형
"A가 B보다 크다고 할 수 있나?"
없다 → 명목형 / 있다 → 순서형
카드 > 현금? 없다 → 명목형
VIP > 골드? 있다 → 순서형
판별 순서
데이터를 보면 이 순서로 물어보세요
① 숫자인가? → 수치형 / 아니면 범주형
② (수치형이라면) 소수가 가능한가? → 연속형 / 정수만이면 이산형
③ (범주형이라면) 순서가 있는가? → 순서형 / 없으면 명목형
